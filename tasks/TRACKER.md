## How we track work (HARD RULE for every developer)
1. **Your work is in Plane before you start it.** Fixes, features, migrations, data fixes, hotfixes,
   investigations and follow-ups all get a CRET ticket with an assignee, however small.
2. **Search before you create. No duplicates.** If a ticket covers it, even someone else's, comment on that one.
3. **This file is generated** (`/project-pm sync`). Never hand-edit it; never copy it into Plane.
4. **No other to-do lists:** not in `todo.md`, handoffs, briefs, PR descriptions or logs.
5. **Move the ticket when the work moves, only as far as In Review.** PR open, merged to `stage` and live on
   `main` all stay In Review, with a comment each time. Client Review, Done and back to In Progress happen only
   on Sadin's word.
6. **Branch and PR carry the ticket id** (`feature/CRET-123-name`, `CRET-123: …`). No id, no merge.
7. **New work found mid-task is a new ticket**, not scope creep.
8. **Questions only the owner can answer are `DECIDE …` tickets**, assigned to the owner.
9. **Unverified isn't done.** Say what you could not prove.
10. **Never delete a ticket.** Won't do → Cancelled, with a comment saying why.
11. **Handoffs come through tickets**, not copy-pasted prompts or handoff files.
12. **Push, merge, and any write to a shared or production database need a human's explicit OK.**
13. **Add one ⏱ time comment per work session** on the ticket.
